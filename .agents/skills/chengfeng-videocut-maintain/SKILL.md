# 维护与排障

先判断用户要解决什么，只读对应模式；不把三个模式顺序跑完，不成为每次剪辑的前置。

| 用户要做什么 | 读取的方法 |
|---|---|
| 启动不了、CLI 找不到、连不上、导出卡住、改完画面不更新；问原因或要求修复 | [排查](references/diagnose.md) |
| 检查版本、有没有新版、更新已指定的 Skill / Plugin / Runtime | [更新](references/updates.md) |
| 整理反馈、上报 Bug、继续提交已展示的 Issue 草稿 | [Bug 反馈](references/report-bug.md) |

“打不开”先排查，不假定需要升级。“检查更新”不包含安装授权。“反馈一下”先给脱敏草稿，不自动提交。如果用户同时要求两种操作，分别核对范围；已有诊断证据可复用，不必重复收集。

共同规则见[工作台接入](references/shared/plugin-access.md)：只处理用户指定产品/组件，缺少本产品 Runtime 不代表没有工作台。首次安装或新增能力按可读的受信安装说明处理，不发明尚未实现的安装 Skill 或 CLI 命令。

分清 Skill 文件、宿主加载、Runtime 启动器、服务身份、项目任务与预览结果。更新/修复不改用户素材、工程或词典；故障知识查所属模块，不把私人日志收进技能包。

交付说明：本次处理模式、实际证据、做过的操作、修后回读与未验证部分。没有真实执行就说“建议/草稿/未提交”，不把 doctor 或文件安装通过说成整个视频流程通过。
